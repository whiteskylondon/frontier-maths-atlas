Lesson 19 · Wing IV — inside the transformer

The residual stream, LayerNorm & RMSNorm

A transformer has one shared memory bus. Every block reads it, computes, and adds its answer back — nothing is ever overwritten.

Level US Graduate · ML FR M2 · ENSAE 3A

Lesson 17 built one attention head; Lesson 18 gave it a sense of position. Neither said how forty of them are wired together. The answer is almost embarrassingly simple: there is one vector per token, and every block adds to it. Read the current vector, normalize a copy, compute something, add the result back — x ← x + f(LN(x)). Because the operation is addition and never assignment, the vector is a running total: what the embedding layer wrote is still literally present forty blocks later, unless some later block explicitly writes its negative. That single design choice buys two things this lesson makes precise. Gradients get a free highway home, so a hundred layers train at all. And blocks can talk to each other privately, by writing into near-orthogonal directions of a wide space — the exponential budget Lesson 10 opened. The normalization layers are the small print: they decide what each block is allowed to see, and they turn out not to be normalizations at all.

The vocabulary, in plain words
  • residual streamthe running total itself: one vector of width dmodel per token, carried from the embedding to the output. Also called the "hidden state". Think of it as a shared blackboard, or a shared memory bus, that every block writes onto.
  • blockone attention sub-layer or one MLP sub-layer. GPT-style models alternate them; each is a separate read-compute-add cycle, so a "40-layer" model performs 80 additions.
  • read / writea block reads the stream through its input projection and writes by adding its output back. Nothing is deleted; "forgetting" can only happen by adding a cancelling vector.
  • skip / identity paththe bare wire that carries x past the block untouched. The other branch is the block. Their outputs are summed — that fan-out is exactly the node whose adjoints add in Lesson 13.
  • feature dimensionthe d coordinates inside one token's vector. Not the batch, not the sequence. Every statistic in this lesson is computed along this axis, one token at a time — say it out loud, because it is the single most-confused fact about LayerNorm.
  • LayerNorm"recentre and rescale this token's own d numbers so they have mean 0 and variance 1, then apply a learned per-feature gain and offset." Two learned vectors, γ and β, both of width d.
  • RMSNormthe same idea with the recentring deleted: divide by the root-mean-square of the token's numbers, apply the gain γ, no offset. What LLaMA-style models use instead of LayerNorm.
  • pre-LN / post-LNwhether the normalizer sits inside the block (x + f(LN(x))) or around the sum (LN(x + f(x))). One trains without a warmup schedule and one does not; the reason is one line of calculus.
  • logit lensreading the partial sum after l blocks as if it were the final answer. Legitimate precisely because the stream is a sum: every intermediate state is a well-formed vector in the same space as the output.
The machinery — one line per block
  • the stream at depth l, one vector in ℝd per token. x₀ is the token embedding plus its positional information (Lesson 18 injects that by rotating queries and keys instead, leaving x₀ purely semantic).
  • block l: an attention sub-layer or an MLP. Its output is a write — a vector added to the stream, not a replacement for it. For attention, Lesson 17's theorem says that write is a convex combination of value vectors.
  • the normalizer, applied to the copy the block reads — never to the stream itself. This is the pre-LN convention, universal since GPT-2. The stream on the left of the plus sign is untouched.
  • the whole lesson. Assignment would destroy information; addition accumulates it. Every claim below is a consequence of this one symbol.

Now unroll the recursion. Substitute x₁ into x₂, x₂ into x₃, and so on. Nothing cancels, because every step only ever adds:

  • the embedding term, still present at full strength in xL. Not approximately, not decayed — it is a literal summand of the final vector.
  • the stream is a flat sum of contributions, one per block. This is an identity, not an approximation or a linearization. The blocks themselves are wildly nonlinear — the combination is additive.
  • logit lenswhy interpretability can attribute the output to individual blocks: apply the final unembedding to any single term and you get that block's own contribution to the logits. The caveat that matters: the terms are not independent — f₂ was computed from x₂, which contains f₀ and f₁. The decomposition is exact; the causal reading is not.

The quadrature law is worth stating plainly. If the writes are unit-length and mutually near-orthogonal, then ‖xl‖² = ‖x₀‖² + Σ‖δ‖² + crosstalk ≈ l + 1, so the stream's norm grows like the square root of the number of writes — and the embedding's share of the direction falls like 1/√(l+1) for exactly the same reason. The gradient consequence — a highway that cannot vanish

Differentiate the update. Lesson 13's rule for a node that feeds two branches is that the two contributions add; here one branch is the block and the other is a bare wire, whose derivative is the identity:

  • the block's own Jacobian, ∂fl(LN(xl))/∂xl — including the normalizer's Jacobian, computed below. Everything the block does is inside this one symbol; the identity beside it is the wire.
  • the surviving term of the expansion. Every other term carries at least one J; this one carries none, so it is depth-independent. A gradient signal can reach x₀ from xL along the skip path alone, multiplied by nothing at all.
  • what you get without the wire — the pure composition. Lesson 9 met this object as the contraction factor |1−ηλ|t: a repeated multiplicative factor decays or explodes geometrically, and only the knife-edge value 1 does neither. Depth is the exponent, so there is no forgiving regime.

Model each block's Jacobian as a fresh random matrix of unit typical gain, scaled by a per-block gain s — the honest toy, since for this question only the gain matters. Push one seeded unit tangent direction through the stack (a forward-mode JVP, Lesson 13) and measure how long it comes out. The two laws are exact in mean square: 𝔼‖Π(I+sJ)u‖² = (1+s²)L and 𝔼‖Π(sJ)u‖² = s2L.

The gap is 8.9e+13 — near fourteen orders of magnitude. The composition path crosses 10⁻⁸, below which no optimizer can act on it, at depth 27, matching ⌈8 ln 10 / ln(1/s)⌉ = 27 exactly. Slide s to 1.00 and the composition survives at 1.445 — the knife edge; slide to 1.50 and it explodes to 1.60e+7. Only the residual path is indifferent. The floor drawn at 1.18e−38 is the smallest normal float32, and no setting on this slider quite reaches it — the deepest, quietest corner, s = 0.20 at depth 40, lands at 1.6e−28 — but extend the stack and it bites: at s = 0.50 the composition path crosses it at depth 127, and past that point the gradient does not merely become small, it rounds to zero.

LayerNorm — along the features, one token at a time
  • mean and variance over the d features of this one token — the sums run over i = 1…d, not over the batch and not over the sequence. Consequence: LayerNorm needs no batch statistics, so it behaves identically at batch size 1, at inference on a single token, and in training. That is why transformers use it and not BatchNorm.
  • learned per-feature gain and offset, each a vector of width d. They are applied after normalizing, so the layer can undo the rescaling it just did — but only in a fixed, learned way, never per-token.
  • a numerical floor, typically 10⁻⁵. It is also the only reason the invariance below is not exact: at σ² = 1 and ε = 10⁻⁵, scaling a token by a = 0.1 shrinks the output by 0.05%. Small, but not zero.
  • with γ = 1, β = 0 and ε = 0, the output norm is always exactly √d. Because Σ(xᵢ−μ)²/σ² = d by construction. At d = 256 that is 16.000, whatever went in. The block downstream cannot know how long the stream was.

That last line is the substance of the layer, so make it precise by differentiating. Write ẑ for the centred input, normalized to unit length:

  • projection onto the all-ones direction — the "add a constant to every feature" direction, killed. Adding b·1 to a token is invisible to LayerNorm.
  • projection onto the token's own direction — the "make this token longer" direction, also killed. Scaling a token is invisible too.
  • since 1ᵀẑ = 0, these two projections are orthogonal, so the bracket is a genuine orthogonal projector of rank d − 2. Verified numerically against central differences: idempotent, trace exactly d − 2, and it annihilates both 1 and ẑ. RMSNorm's Jacobian is (I − x̂x̂ᵀ)/rms — rank d − 1, one dimension richer, because it only throws away scale.
RMSNorm — the same layer with two things deleted
  • the mean square, not the variance. One reduction over the features, and no subtraction. LayerNorm needs μ before it can accumulate Σ(xᵢ−μ)² — two dependent passes over the vector (fusable into one via 𝔼[x²]−μ², at a cost in numerical stability). RMSNorm needs one pass, full stop.
  • what is droppedthe mean subtraction and the offset β. β is d parameters per norm: for a 4,096-wide model with two norms in each of its 32 layers — one per sub-layer, in this lesson's vocabulary one per block — 4,096 × 2 × 32 = 262,144 parameters that simply stop existing.
  • the condition under which the two layers coincide exactly — ε included, to machine precision. If x is already mean-zero then σ² is the mean square, and centring does nothing. Once the mean is not zero they genuinely differ.
  • invariances keptRMSNorm keeps scale-invariance and loses shift-invariance: RMS(ax) = RMS(x) for a > 0, but RMS(x + b1) ≠ RMS(x). Its invariance group is one-dimensional instead of two, which is exactly why its Jacobian has rank d − 1 instead of d − 2.
Pre-LN or post-LN — one plus sign, two training regimes

Post-LN, the original 2017 wiring, is x ← LN(x + f(x)): the normalizer sits around the sum, so the skip path passes through it too. Pre-LN, universal since GPT-2, is x ← x + f(LN(x)): the normalizer sits inside the block and the wire is untouched. Differentiate both and the difference is stark. Pre-LN gives ∂xl+1/∂xl = I + Jl — the clean identity term from the section above. Post-LN gives Ll(I + Jl) — now with Jl = ∂fl/∂xl, no normalizer inside it — where Ll is the normalizer's Jacobian: a rank-(d−2) projector scaled by 1/σ. Every skip step is now multiplied by something, so the free identity path is gone and you are back to a product of L matrices — Lesson 9's contraction factor with the depth as its exponent. That is why deep post-LN transformers need a learning-rate warmup (the early updates are large where the product is badly scaled, and diverge without it), and why pre-LN trains from step one at full learning rate. The price of pre-LN is the twist below: the stream itself is never normalized, so its norm grows without bound, and a single final LayerNorm before the unembedding is what rescues the logits.

The same object on a trading book

A book's end-of-day PnL is a residual stream. The attribution system starts from yesterday's mark and each desk adds its contribution to a running total; nothing is overwritten, which is exactly why the final number decomposes into per-desk terms with no remainder:

  • desk k's contribution — the analogue of one block's write. The sum is the logit lens: read the total after k desks and you have a well-formed partial PnL in the same units as the final one.
  • the normalization step: divide each desk's number by its own risk before comparing them. Like LayerNorm, it is applied to the copy you look at, never to the ledger — you scale to compare, you sum unscaled to account. Scaling the ledger would break the identity.
  • the crosstalkthe decomposition is always exact; it is only interpretable per-desk when the desks' books are near-orthogonal. Two desks running the same trade produce an exact sum whose split is arbitrary — the collinearity of Lessons 5 and 7, and the same crosstalk term you measured in the panel above.

The precise statement

Let xl+1 = xl + fl(LN(xl)) for l = 0,…,L−1. (i) Unrolling. xL = x₀ + Σl=0L−1 fl(LN(xl)) identically — an exact decomposition of the final state into the embedding plus one term per block, valid however nonlinear the fl are. (ii) Jacobian. With Jl = ∂fl(LN(xl))/∂xl, ∂xL/∂x₀ = ∏l(I + Jl), whose expansion contains the term I with no factor of any Jl; hence the map from xL-sensitivity to x₀-sensitivity is the identity plus corrections, and cannot vanish geometrically in L through the skip path, whereas the pure composition obeys ‖∏lJl‖ ≤ ∏l‖Jl‖, so a uniform bound ‖Jl‖ ≤ c < 1 forces decay at least as fast as cL, while Jl = c·Ql with Ql orthogonal attains ‖∏lJl‖ = cL exactly: the composition path is geometric in the depth, with no identity term to protect it in either direction. (iii) LayerNorm's invariance. At ε = 0 and for any a > 0, b ∈ ℝ, LN(ax + b·1) = LN(x): the invariance group is two-dimensional, the layer is constant on each orbit {ax + b1}, and with γ = 1, β = 0 its image is {z : 1ᵀz = 0, ‖z‖ = √d} — the radius-√d sphere inside the mean-zero hyperplane, a surface of dimension d − 2. Accordingly ∂LN/∂x = σ⁻¹(I − 11ᵀ/d − ẑẑᵀ) is σ⁻¹ times an orthogonal projector of rank d − 2. (iv) RMSNorm. RMS(x) = γ ⊙ x/√(mean(x²)+ε) is invariant to positive scaling only; its Jacobian has rank d − 1; and whenever 1ᵀx = 0 it agrees with LN(x) exactly, ε included.

The twist — LayerNorm is not a normalization, it is a projection

Count the dimensions. LayerNorm's invariance group has two parameters (a scale and a shift), so it destroys two dimensions of information at every block and its Jacobian is exactly a rank-(d−2) projector, divided by σ. The image is a (d−2)-dimensional sphere: only the direction survives. A token's magnitude is not attenuated, it is annihilated — every downstream block sees a vector of length exactly √d (at γ = 1, β = 0) no matter what arrived. So if a model wants to encode "how strongly" as well as "what", it has to re-encode strength as direction, which is precisely why mechanistic interpretability speaks in directions and features rather than magnitudes, and why superposition (Lesson 20) is a story about angles in Lesson 10's exponentially large budget of near-orthogonal slots — 8×10⁸ of them at ε = 0.1 in a 4,096-wide stream. Second barrel: because the normalizer sits inside the block and the wire is untouched, the residual stream is the only object in a pre-LN transformer that is never normalized. Its norm grows monotonically with depth — the √(l+1) law you measured — so the stream's magnitude is not a meaningful quantity, merely a count of how many blocks have written. Real models exploit this: a block can make itself quieter over training simply by keeping its write norm fixed while the stream grows around it. And since nothing rescales the stream, one final LayerNorm before the unembedding is doing all of the work of turning a vector that has been growing for forty blocks into logits of sane size.

Why this matters · volarixs

The Cross-Matrix's additive reading is the unrolling identity. A target move decomposed as Σk βr,kΔxk is a residual stream with one write per driver, and the z-scored driver panel is the normalization step: you rescale each driver to compare elasticities, then sum the unscaled contributions to account. Same discipline as pre-LN — normalize the copy you read, never the ledger.

And the crosstalk warning transfers exactly. Lesson 7 showed the driver panel is deliberately collinear (dispersion at five horizons plus their z-scores), so XᵀX is ill-conditioned and the per-driver split of an exact total is unstable even though the total is not — which is why sign_stability, not the t-stat, is the gate on any single cell. A near-orthogonal set of writes gives a decomposition you can read term by term; a collinear one gives a sum you can trust and an attribution you cannot.
