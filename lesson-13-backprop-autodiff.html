Backprop as automatic differentiation

Backpropagation isn't a neural-net trick — it's the chain rule, run backward through a graph, in one pass.

LevelUS Advanced undergrad → graduateFR Master M1 · ENSAE 2A

Lesson 9's optimizers all needed one thing: the gradient ∇L. Backpropagation is how you get it — cheaply, for millions of parameters at once. The idea is exact and simple: write the computation as a graph of elementary operations, do a forward pass to compute values, then a backward pass that pushes derivatives from the output back to every input by multiplying local derivatives along the way. That's the chain rule as bookkeeping — reverse-mode automatic differentiation.

The chain rule, made mechanical

Reverse mode computes this efficiently by assigning every node an adjoint and sweeping from output to inputs. Each node's adjoint is its local derivative times the adjoints of the nodes it feeds — and when a node feeds several places, those contributions add:

  • forwardvalues flow input → output. Compute and cache every node's value; this is just evaluating the function.
  • v̄ = ∂L/∂vthe adjoint of node v. How much the final loss moves per unit change in v — the thing you want for every parameter.
  • Σ childrena node feeding several places. Its adjoint is the SUM over all the branches it influences — the most-missed rule.

The precise statement

Reverse-mode AD computes the gradient of one scalar output with respect to all inputs in time proportional to the cost of one forward evaluation (times a small constant), by traversing the computation graph in reverse topological order and accumulating adjoints v̄ = Σ_{c∈children} c̄ · ∂c/∂v. It is exact (not finite-difference) — each adjoint is a vector-Jacobian product with the node's local Jacobian. Forward mode instead propagates one input's perturbation to all outputs (a Jacobian-vector product); reverse mode is preferred whenever outputs ≪ inputs, e.g. a scalar loss over millions of parameters.

The twist — this is exactly how you'd compute every Greek at once

Reverse-mode's whole advantage is direction: one output, many inputs, all sensitivities in a single backward pass. That's precisely the shape of a Greeks calculation — one price V, and you want ∂V/∂S, ∂V/∂σ, ∂V/∂r, ∂V/∂t all together. Bump-and-revalue (finite differences) costs one extra revaluation per input and adds truncation error; reverse-mode AD — "adjoint algorithmic differentiation," now standard in derivatives libraries — gets the entire gradient for roughly the price of one valuation, exactly. The mirror image also matters: if you have one input and many outputs (how a single shock propagates through a whole book), forward mode is the efficient one. Same chain rule, two sweep directions; which is cheaper depends only on the shape of the Jacobian — tall (many outputs) favours forward, wide (many inputs, scalar loss) favours reverse. Deep learning is the extreme wide case, which is why backprop won.

Why this matters · volarixs

The graph above is the literal gradient step from Lesson 9, now itemised: change a loading w₁ and the backward pass tells you ∂L/∂w₁ = (tanh′·x₁)·2(p−y) — the number your optimizer subtracts. Any gradient-trained model you build (a neural forecaster, a logistic direction signal, a calibration objective) is differentiated exactly this way, and every framework — PyTorch, JAX — is just a graph builder plus this reverse sweep.

The transferable instinct for your derivatives work: when you need many sensitivities of a single quantity — a book's Greeks, a portfolio's exposures to every factor — reach for adjoint/reverse-mode, not per-input bumping. It's exact and it's one pass. And note ∂L/∂x is computed too: the model hands you the sensitivity of its loss to the inputs, not just the weights — useful for attribution and for adversarial/robustness checks.
